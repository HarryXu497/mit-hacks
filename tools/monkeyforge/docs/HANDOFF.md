# MonkeyForge handoff

This is the current state of the HackMIT MonkeyForge character pipeline. The working directory is
`C:\Users\caeca\Code\MonkeyForge`.

## What exists now

- FastAPI orchestration: sketch + description -> `CharacterSpec` -> accessory geometry -> Blender
  compilation -> validated GLB.
- Local mock mode works with no GPU. The mock provider now creates a small low-poly helmet for hats
  and keeps the HTTP worker boundary ready for a real generator.
- Four original, procedural, rigged low-poly monkey bodies are generated by
  `scripts/blender_build_original_base.py`:

  - balanced
  - runner
  - defender
  - goalkeeper

- Each base has the canonical seven sockets and a standard monkey skeleton. The current body parts
  use rigid per-part weights; this is enough to test socket attachments, but it is not final
  production deformation.
- Base/profile selection is wired through `CharacterSpec.archetype` and `BlenderCompiler`.
- Blender preview materials use a cel/toon BSDF with hard light bands. GLB export happens before the
  preview-only node conversion, and the preview renderer applies toon materials after GLB import.
  Freestyle outlines are enabled in the preview renderer.
- Downloaded BTD6 models are stored under `assets/reference/btd6_prototype/` and are git-ignored.
  They are private style/topology references only and must not enter the public repository,
  training set, or released game.

## Measurement and feature extraction

Every compiled asset is now measured once by `scripts/blender_measure_glb.py`, which writes
`output/measurement.json` next to the GLB. Both hard validation and ranker features read that
document, so a candidate is opened in Blender exactly once.

Validation is no longer file-size-only. It fails an asset for missing sockets, an accessory that
resolved to no mesh, or a triangle count above twice its target, and warns on fragmentation and a
socket outside the accessory bounding box. `ValidationMetrics.measured` distinguishes "inspected and
clean" from "never inspected" — the passthrough compiler path still reports `measured=false`.

Three of the six ranker features are now computed rather than hand-entered:

```text
socket_fit_score        socket-to-bounding-box gap, normalised by accessory diagonal
triangle_budget_score   full marks within budget; overruns decay, <50 triangles is degenerate
disconnected_penalty    islands beyond the declared part_schema count
```

`target_triangles` is a **ceiling, not a quota**. `spec_provider.py` hardcodes 2500 for every
accessory, so it was never a per-prop target to hit; a prop that reads correctly with fewer
triangles is better, not worse. Degeneracy is therefore an absolute floor
(`MINIMUM_VIABLE_TRIANGLES = 50`) rather than a fraction of the ceiling. If the spec provider ever
sets real per-kind targets, revisit this.

`silhouette_score` and `palette_score` are measured from a render by `features.image_features` and
need the `imaging` extra (`pip install -e .[imaging]` — numpy and pillow, without torch).
`semantic_similarity` still needs a frozen visual encoder and defaults to a neutral 0.5. Unmeasured
dimensions default to 0.5 rather than to a flattering value.

Three traps that measurement already caught, worth keeping in mind when extending it:

- glTF splits vertices at every hard edge and UV seam, so counting connected components on raw
  imported topology reports a flat-shaded cube as six parts. The measurement pass welds coincident
  vertices first; without that the goalkeeper helmet reported 56 islands instead of 2.
- Socket fit must be measured as a gap to the bounding box, not a distance to its centre. A hat
  correctly seated on `SOCKET_HEAD_TOP` legitimately extends upward, so centre-distance penalises
  exactly the props that are right.
- `blender_render_preview.py` sets `film_transparent = False`, so the review renders are fully
  opaque and an alpha mask selects the whole frame. `features._subject_mask` falls back to inferring
  the background from the border ring; without that every silhouette scored 0.0 and every palette
  score sat at a near-constant 0.70.
- **Measure generator quality on the raw accessory, not the compiled character.**
  `blender_compile.py` re-seats the prop onto its socket (lines 82-88) and decimates it to budget
  (lines 93-103). Both are correct compiler behaviour, and both destroy exactly what
  `socket_fit_score` and `triangle_budget_score` are trying to observe: measured after compilation
  they are constant by construction, and the ranker gives them zero weight. Measure the raw asset
  with `blender_measure_glb.py --bare`, which treats every mesh as the accessory and uses the world
  origin as the socket. The compiled GLB is still what gets rendered for the image features.

## Building preference data

`scripts/generate_candidates.py` builds a labelable candidate set locally with no GPU. It generates
procedural accessory variants from `src/monkeyforge/variants.py` spanning clean to deliberately
broken — floating off the socket, fragmented into loose islands, over the triangle ceiling,
degenerate — so the geometric features have something to discriminate and the pairs are worth a
human's time.

```powershell
.\.venv\Scripts\python.exe scripts\generate_candidates.py --output-dir output\candidates
```

Fourteen candidates take roughly two minutes. Then:

```powershell
# 1. generate candidates, or list your own in a candidates.jsonl:
#    {"id":..., "prompt":..., "provenance":..., "render":..., "features":...}
.\.venv\Scripts\python.exe scripts\review_pairs.py plan `
  --candidates output\candidates\candidates.jsonl --output output\review\pairs.csv

# 2. open each a_render/b_render, type a or b in the choice column, save

# 3. turn the labelled CSV into a training dataset
.\.venv\Scripts\python.exe scripts\review_pairs.py build `
  --candidates training\candidates.jsonl --review output\review\pairs.csv `
  --output training\dataset.jsonl
```

A prompt needs at least two candidates before it produces a pair. `review_manifest.jsonl` currently
holds four baselines and one candidate, so it yields no pairs as-is.

`build` merges image features measured from each candidate's `render` over the geometric features in
its `features.json`, because the pipeline writes `features.json` before anything is rendered and
leaves silhouette and palette at neutral placeholders. Give every candidate its **own**
`features.json`: the ranker learns only from features that differ within a pair, so candidates
sharing one file train a model that ignores geometry entirely.

## Training strategy

Do not train a 3D foundation model first. The staged strategy is:

1. Freeze the image-to-3D generator and collect team-owned candidate renders.
2. Ask humans for preferred/rejected pairs for the same prompt.
3. Train the small pairwise style ranker in `src/monkeyforge/ranking.py`.
4. Add frozen visual embeddings (CLIP/DINO/render encoder) to the six current hard/style features.
5. Only after a few hundred consistently rendered original props consider a narrow LoRA or
   project-specific 3D fine-tune.

Current ranker features:

```text
semantic_similarity
silhouette_score
palette_score
socket_fit_score
triangle_budget_score
disconnected_penalty
```

Run the plumbing smoke training with:

```powershell

  --dataset training\dataset.example.jsonl `
  --output output\training\style-ranker.json
```

The example data is synthetic plumbing data, not a visual-quality claim. Replace it with original
team renders and real human choices before reporting a learned metric.

## Real GPU worker boundary

Set these in `.env` when a Linux/CUDA worker is available:

```dotenv
MONKEYFORGE_PROVIDER=http
MONKEYFORGE_GPU_ENDPOINT=https://worker.example/v1/image-to-3d
MONKEYFORGE_GPU_TOKEN=...
MONKEYFORGE_COMPILER=blender
```

The request contract is in `docs/gpu-worker-contract.md`: multipart reference image, prompt, seed,
triangle target, and part schema; response is a binary GLB. Keep Pixal3D/TRELLIS.2 dependencies in
the worker environment rather than installing them into the API venv.

A worker implementing that contract lives in `worker/`, with the runbook in `worker/README.md`. Its
generator is pluggable:

> **Current blocker (2026-09-19).** The GX10 is fully built — CUDA 13 toolkit, torch 2.14+cu130,
> `flex_gemm`/`cumesh`/`o_voxel` all compiled for `sm_121`, and a hand-written sparse `sdpa` attention
> backend verified to ~1e-6 against a naive reference. All 16.24 GB of TRELLIS.2-4B weights are
> downloaded. Generation is blocked on one thing only: `facebook/dinov3-vitl16-pretrain-lvd1689m` is a
> **gated** HuggingFace repo and returns `GatedRepoError: 401`. It needs a human to accept Meta's
> licence and set `HF_TOKEN`; see step 5 of `worker/README.md`. The **stub** generator path is
> deployed and verified end to end over the network, so everything except TRELLIS itself is proven.

```text
worker/server.py               contract endpoint, bearer auth, warm-on-startup, response cache
worker/generators/stub.py      procedural GLB, no GPU, no weights
worker/generators/trellis.py   TRELLIS.2 adapter; the marked block needs verifying on the box
worker/generators/glb.py       minimal binary glTF writer, no dependencies
worker/probe_trellis.py        prints the real TRELLIS API surface and which CUDA extensions loaded
worker/setup_gx10.sh           stage 1 setup for the GX10 (arm64 DGX OS)
```

Install the contract with the stub first and prove the network path; only then install TRELLIS.2.
Doing both at once makes a failure ambiguous between CUDA, multipart, auth, and export.

`tests/test_http_provider.py` pins the orchestrator half of the contract against a fake worker, so a
failure against a real one means the worker is wrong rather than the client being unchecked.

## Known limitations / next work

- Rigid per-part weights need real smooth deformation weights and a small animation test set.
- The original bases are deliberately low-poly prototypes; refine face topology, eye highlights,
  mouth expressions, jersey seams, and palette application after the gameplay loop is stable.
- The compiler currently compiles the first accessory in a spec. Add multi-accessory compilation
  and rank multiple candidates before the GPU demo.
- The trained ranker is still never loaded at inference. `RankerArtifact.score()` has no caller, so
  `output/training/style-ranker.json` has no effect on which candidate is chosen. This lands
  together with multi-accessory/multi-candidate compilation.
- `tests/test_ranking.py` asserts `pairwise_accuracy == 1.0` on four synthetic examples with six
  free parameters, which is trivially separable. Relax that bound when real labels replace the
  example dataset; the drop is expected, not a regression.
- Texture dimensions are still unvalidated.
- Keep BTD6 reference downloads local and ignored; replace any public-facing art with team-owned or
  properly licensed assets.
